# Аддоны — что это и как их делать

Слово «аддон» в Minecraft означает разные вещи в зависимости от платформы. Ниже —
все значения с указателем, где искать детали.

## 1. Аддоны для Bedrock Edition (самое частое значение)

На Bedrock нет модов на Java. Вместо них — **аддоны** из поведенческих и ресурсных
пакетов. Подробно — в `guides/bedrock-from-zero-to-addon.md`.

Состав аддона:

- **Ресурсный пакет** (`resource_pack`) — текстуры, звуки, модели, интерфейс, шрифты.
- **Поведенческий пакет** (`behavior_pack`) — логика: новые мобы, предметы, блоки,
  рецепты, лут, события.
- **Скрипты** (`@minecraft/server`) — JavaScript-API для сложной логики.

Формат — папка с `manifest.json` в корне, упакованная в `.mcaddon` (zip из обоих
пакетов) или `.mcpack` (один пакет).

## 2. Аддоны для Java-ядер (Fabric/Forge/NeoForge/Quilt)

В Java-моддинге «аддон» — это **мод, который расширяет другой мод**. Технически он
не отличается от обычного мода, но:

- в зависимостях (`depends`/`[[dependencies]]`) указывается мод-хост;
- код использует **публичный API** мода-хоста;
- версия аддона обычно привязана и к версии Minecraft, и к версии хоста.

Примеры: дополнения к крупным модам (Create, Mekanism, AE2) — это обычные моды с
жёсткими зависимостями.

Что важно:

- **Читать API хоста.** Не лезть в `internal`-классы: при обновлении они ломаются.
- **Правильно объявлять зависимость** в манифесте, иначе аддон загрузится без хоста
  и упадёт.
- **Версионировать по хосту**: `1.20.1-create-0.5.1-fabric` и т.п.

## 3. Аддоны для плагинов (Bukkit/Spigot/Paper)

Обычный плагин, который расширяет другой плагин:

- объявляет `depend:` или `softdepend:` в `plugin.yml`;
- обращается к API хоста через его сервисы или `Bukkit.getPluginManager().getPlugin(...)`;
- регистрирует свои команды и события рядом с хостом.

Примеры: дополнения к LuckPerms, WorldGuard, Vault-провайдеры, дополнения к
EssentialsX.

Ключевой момент — `softdepend` вместо `depend`, если аддон может работать и без
хоста (с урезанным функционалом).

## Как выбрать, что именно делать

- Minecraft Bedrock (мобильный/консоль/Windows Bedrock) → **аддон-пакеты**, см.
  `guides/bedrock-from-zero-to-addon.md`.
- Minecraft Java, расширение крупного мода → **мод-аддон**, см.
  `guides/from-zero-to-jar.md` и гайды по конкретному ядру.
- Java-сервер, расширение плагина → **плагин-аддон**, см.
  `guides/plugins-from-zero-to-jar.md`.

## Общее правило для любых аддонов

1. Хост — это зависимость, объявленная явно.
2. Использовать только публичный API хоста.
3. Не дублировать функционал хоста, а расширять его.
4. Тестировать с точной версией хоста, под которую собран аддон.
5. Проверять загрузку: если хоста нет, аддон не должен падать молча — лучше
   понятная ошибка в логе.
