# Нерешаемые сборки: что не собирается и почему

> Проверено 2026-10-21. Документ описывает случаи, когда **сборка мода не проходит
> по объективным причинам** — не из-за ошибки в коде, а из-за отсутствия поддержки
> со стороны ядра, маппингов или библиотек. Здесь же — как такие случаи обходить.

Главное правило: **если ядро или маппинги не поддерживают версию игры, никакой
код это не исправит.** Нужно либо понизить версию игры, либо сменить ядро, либо
подождать релиз маппингов и библиотек.

---

## 1. Как отличить «не собирается» от «код плохой»

| Признак | Плохой код | Ядро не поддерживает |
|---|---|---|
| Ошибка компилятора про твой класс/метод | да | нет |
| Ошибка резолва версии (`Could not find ...`, `No matching version`) | нет | да |
| Маппинги не найдены (`mappings ... not found`) | нет | да |
| `BUILD SUCCESSFUL`, но jar пустой (нет `.class`) | нет | да |
| Библиотека ядра отсутствует под нужную версию игры | нет | да |

**Обязательная проверка после сборки:** распаковать jar и убедиться, что внутри есть
`.class`-файлы. `BUILD SUCCESSFUL` сам по себе **не** означает, что мод рабочий.

## 3. Quilt на Minecraft 26.x и 1.21.x — не собирается

### Причина

Три независимые проблемы складываются вместе.

1. **Маппинги Quilt** есть только до **1.21.11** — как и Yarn.
2. **`quilted-fabric-api`** выпущен только под **1.20.6 и 1.21**; под **1.21.1 его нет**
   (нестыковка версий Fabric API).
3. **QSL** (Quilt Standard Libraries) — это **pom-агрегатор** (`packaging: pom`,
   группа `org.quiltmc.qsl`), а не jar. Под 1.21.11 его тоже нет.

Полный набор библиотек сходится **только на 1.20.6** — там собирается стабильно.

### Ловушка meta-сервиса

Сервис `meta.quiltmc.org/v3/versions/game` показывает версию **26.3**, и загрузчик
Quilt **существует** под 26.3. Но это **не значит**, что мод соберётся: реальную
поддержку определяют **маппинги**, а не список версий ядра.

### Ловушка пустого jar

Если в `build.gradle` нет ни одного `modImplementation` (например, забыли QSL или
`quilted-fabric-api`), Loom ремапит **0 модов** → получается **пустой jar ~261 байт**.
Сборка при этом заканчивается `BUILD SUCCESSFUL`.

Как диагностировать: в логе должно быть `:remapping N mods from modImplementation`
(в эталонном 1.20.6 — `53 mods`). Если строки нет или `N = 0` — jar будет пустым.

Замечание: `devlibs/<имя>-dev.jar` при этом **всегда полный** — проверять надо именно
итоговый `build/libs/*.jar`.

### Версии деталей
- Quilt Loom **1.8.5 требует Gradle ≥ 8.10** (wrapper шаблона 8.9 падает).
- Точка входа: `org.quiltmc.loader.api.minecraft.ModInitializer` есть **только в master**;
  в релизах (0.31) используется `net.fabricmc.api.ModInitializer` — метод
  `onInitialize()` **без аргументов**, интерфейс расширяет `GameEntrypoint`.

### Что делать
- Собирать Quilt под **1.20.6** (там сходится весь набор библиотек).
- Для новых версий — брать Fabric или NeoForge.

## 4. Почему «одним javac» не собрать плагин Paper

`paper-api` тянет **транзитивные зависимости** (приключенческая библиотека adventure и
др.). Одиночный `javac` их не подхватит — сборка обязана идти через **Maven или Gradle**.

- API: `https://fill.papermc.io/v3/projects/paper/versions/<версия>/builds`
- Репозиторий артефактов: `https://repo.papermc.io/repository/maven-public/`
- `api-version` в `plugin.yml` = версия сервера (например, `26.3`).

---

## 5. Общая стратегия для неподдерживаемой версии

1. **Проверить поддержку по маппингам/библиотекам**, а не по списку версий ядра.
2. Если поддержки нет — **понизить версию игры** до последней поддерживаемой.
3. Если нужна именно новая версия — **сменить ядро** на то, чьи маппинги не отстают
   (Fabric/NeoForge под 26.x — там официальные маппинги Mojang).
4. Собрать, затем **проверить непустоту jar**.
5. Только после этого считать мод готовым.
